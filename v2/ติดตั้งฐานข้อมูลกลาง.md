# คู่มือติดตั้งฐานข้อมูลกลาง (v3)

ระบบทะเบียนผู้นมัสการ · คริสตจักรคอร์เนอร์สโตน หัวหิน
จัดทำระบบโดย มน.สมเจต เสมาทอง ประธานธรรมกิจคริสตจักร

---

## CEO ACTION REQUIRED — ทำ 6 ขั้นนี้ตามลำดับ

1. สร้างสเปรดชีตใหม่ 1 ไฟล์ (sheets.new) → เก็บ **ID** ไว้ (ID คือส่วนระหว่าง `/d/` และ `/edit` ใน URL)
2. เปิด **script.new** → ลบ `function myFunction() {}` → วางไฟล์ `apps-script/Code.gs` ทั้งไฟล์ → บันทึก
3. เฟือง **Project Settings → Script properties** → ใส่ 5 ค่าตามตารางในขั้นที่ 3 ด้านล่าง
4. กลับหน้าโค้ด → เลือกฟังก์ชัน `makePepper` → **Run** → กด Allow เมื่อขออนุญาต
5. **Deploy → New deployment → Web app** (Execute as: **Me** · Who has access: **Anyone**) → คัดลอก Web app URL
6. อัป `index.html` ขึ้น GitHub ที่โฟลเดอร์ `v2/` → เปิดลิงก์ → วาง URL → กดทดสอบ → ตั้งบัญชีผู้ดูแลคนแรก (**รหัสอย่างน้อย 8 ตัว**)
7. ทดสอบบนมือถือตามขั้นที่ 7 ก่อนแจกลิงก์ให้ทีมงาน

ติดขั้นไหนให้แจ้งหมายเลขขั้นนั้น ไม่ต้องเดา

**ตรวจการกรองข้อมูลตามสิทธิ์ (ทำได้หลังขั้นที่ 4)** — เลือกฟังก์ชัน `checkColumnAccess` → **Run** → เปิด Execution log จะเห็นว่าหัวตารางจริงของคุณ คอลัมน์ใดถูกส่งให้ Admin / Editor / Viewer บ้าง ใช้ยืนยันว่า Viewer ไม่ได้รับเบอร์โทรและวันเกิด

## อ่านก่อนเริ่ม

- **ไม่ต้องแตะ Apps Script เดิม** โปรเจกต์นี้เป็นแบบแยกอิสระ (standalone) ไม่ผูกกับสเปรดชีตใด ไม่กระทบ AppSheet · ถ้าจำเป็นต้องแก้สคริปต์เดิมของคุณเมื่อใด ให้ File → Make a copy สำรองก่อนทุกครั้ง
- **ระบบเดิมบน GitHub ยังใช้งานได้อยู่ ให้คงไว้เป็น backup** ไฟล์ชุดนี้ให้ทดสอบในโฟลเดอร์ `/v2/` ก่อน ยังไม่ต้องทับหน้าแรก
- **ไม่ต้องส่งรหัสหรือกุญแจใดในแชท** ความลับทุกค่าอยู่ในฝั่ง Google เท่านั้น และไฟล์ `index.html` บน GitHub ไม่มีรหัส ไม่มีกุญแจ ไม่มีข้อมูลสมาชิก

## ขั้นที่ 1 · สเปรดชีตที่ต้องใช้

1. สร้างสเปรดชีตใหม่ 1 ไฟล์ (sheets.new) ชื่อเช่น "ระบบทะเบียน — บัญชีผู้ใช้"
2. เก็บ **ID** ของทั้ง 3 ไฟล์ไว้ — ID คือส่วนที่อยู่ระหว่าง `/d/` และ `/edit` ใน URL
   - ไฟล์ใหม่ที่เพิ่งสร้าง → *ID บัญชี*
   - ไฟล์ทะเบียนสมาชิกของคุณ → *ID ทะเบียน* + ชื่อแท็บ
   - ไฟล์บันทึกลงชื่อนมัสการ → *ID นมัสการ* + ชื่อแท็บ

สองไฟล์หลังระบบ **อ่านอย่างเดียว** ไม่มีการเขียนทับ

## ขั้นที่ 2 · สร้างโปรเจกต์ Apps Script ใหม่

1. เปิด script.new (ได้โปรเจกต์เปล่า ไม่ผูกกับชีตใด)
2. ตั้งชื่อ "ระบบทะเบียนผู้นมัสการ — Backend"
3. ลบ `function myFunction() {}` ที่เป็นข้อความตัวอย่างในไฟล์เปล่านั้น แล้ววางเนื้อหา `apps-script/Code.gs` ทั้งไฟล์ → บันทึก

## ขั้นที่ 3 · ใส่ค่าตั้งต้น

เฟือง **Project Settings** → **Script properties** → Add ทีละรายการ

| Property | Value |
|---|---|
| `ACCOUNTS_SHEET_ID` | *ID บัญชี* |
| `MEMBERS_SHEET_ID` | *ID ทะเบียน* |
| `MEMBERS_TAB` | ชื่อแท็บทะเบียน (เว้นว่าง = แท็บแรก) |
| `ATT_SHEET_ID` | *ID นมัสการ* |
| `ATT_TAB` | ชื่อแท็บนมัสการ (เว้นว่าง = แท็บแรก) |

กลับไปหน้าโค้ด → เลือกฟังก์ชัน **`makePepper`** → **Run** (สร้างค่าลับของเซิร์ฟเวอร์ให้เองแบบสุ่ม คุณไม่ต้องพิมพ์และไม่ต้องรู้ค่านี้)
ครั้งแรกจะขออนุญาต: Review permissions → เลือกบัญชีของคุณ → Advanced → Go to … → **Allow**

## ขั้นที่ 4 · เผยแพร่เป็น Web App

**Deploy → New deployment** → เฟืองข้าง Select type → **Web app** → Execute as: **Me** · Who has access: **Anyone** → Deploy → คัดลอก **Web app URL** (ลงท้าย `/exec`)

> "Anyone" หมายถึงเว็บของเราติดต่อเข้ามาได้ ไม่ได้หมายถึงใครก็เห็นข้อมูล — ทุกคำสั่งตรวจตัวตนและสิทธิ์ที่เซิร์ฟเวอร์ก่อนทุกครั้ง และ `doGet` ให้เฉพาะการตรวจสถานะ ไม่คืนข้อมูลใด

## ขั้นที่ 5 · ผูกหน้าเว็บ (ทดสอบใน /v2/ ก่อน)

1. อัป `index.html` ขึ้น GitHub ที่โฟลเดอร์ `v2/` → ได้ลิงก์ `…github.io/member-register/v2/`
2. เปิดลิงก์ → หน้า **"ยังไม่ได้ผูกกับฐานข้อมูลกลาง"** → วาง Web app URL → **ทดสอบและเชื่อมต่อ**
3. หน้าเปลี่ยนเป็นเข้าสู่ระบบ พร้อมกล่อง **"ตั้งค่าครั้งแรก — สร้างบัญชีผู้ดูแล"** → ตั้งชื่อผู้ใช้และรหัสผ่านเอง (≥ 8 ตัว) → สร้าง
   ระบบเข้าสู่ระบบให้ทันที และ **ปิดช่องนี้ถาวร** ไม่มีใครสร้างผู้ดูแลเพิ่มได้อีก
4. กด **โปรไฟล์ → 💾 บันทึก** จะได้ `index.html` ที่ผูก URL ไว้แล้ว → อัปทับที่ `v2/index.html` (ครั้งเดียว เพื่อให้ทีมงานไม่ต้องกรอก URL)

## ขั้นที่ 6 · รายการทดสอบก่อนย้ายมาหน้าแรก

1. เข้าด้วยบัญชีผู้ดูแล → เห็นรายชื่อและประวัตินมัสการจากชีตจริง
2. เพิ่มบัญชีที่ 2 (Viewer) และที่ 3 (Editor) → กำหนดรหัสเอง
3. เปิดจากมือถือ/หน้าต่างส่วนตัว → เข้าด้วย Viewer → เห็นข้อมูล ไม่มีปุ่มผู้ดูแล แก้ไขไม่ได้
4. เข้าด้วย Editor → แก้ผลพิจารณาและบันทึกได้ แต่ไม่เห็นการจัดการบัญชี
5. ตั้งรหัสใหม่ให้บัญชีหนึ่ง → เครื่องที่ยังเปิดค้างของบัญชีนั้นต้องถูกตัดทันที
6. ปิดบัญชี → รีเฟรชแล้วต้องเข้าไม่ได้
7. แก้ผลพิจารณา 1 รายชื่อ → เปิดจากอีกเครื่องต้องเห็นค่าเดียวกัน

ผ่านทั้ง 7 ข้อแล้วจึงย้าย `v2/index.html` มาทับ `index.html`

## ขั้นที่ 7 · ทดสอบบนมือถือและแท็บเล็ต (สำคัญ — ทำก่อนแจกลิงก์)

ทดสอบอย่างน้อย 2 เครื่อง เช่น Chrome บน Android และ Safari บน iPhone หรือ iPad

| ทดสอบ | ผลที่ถูกต้อง |
|---|---|
| เปิดลิงก์ `/v2/` บนมือถือ | เห็นหน้าเข้าสู่ระบบ ตัวหนังสืออ่านได้ ไม่ต้องซูม |
| ล็อกอินด้วยบัญชีผู้ดูแล | เข้าได้ ตารางแสดงครบ เลื่อนดูได้ |
| กดปุ่มโปรไฟล์ → จัดการบัญชี | ปุ่มกดติดทุกปุ่ม ช่องกรอกใช้งานได้ |
| เพิ่มบัญชีจากมือถือ | บันทึกสำเร็จ และเห็นบัญชีใหม่ทันที |
| ล็อกอิน Viewer บนอีกเครื่อง | เห็นข้อมูล ไม่มีปุ่มผู้ดูแล |
| ปิดเบราว์เซอร์แล้วเปิดใหม่ | กลับมาที่หน้าเข้าสู่ระบบ (ไม่ค้างข้อมูลไว้ในเครื่อง) |
| เปิดใน Safari โหมดส่วนตัว (Private) | ยังเข้าใช้งานได้ปกติ |

**หากขึ้นข้อความเหล่านี้ ให้แก้ตามที่ระบุ**

| ข้อความที่เห็น | สาเหตุและวิธีแก้ |
|---|---|
| "ฐานข้อมูลกลางขอให้ลงชื่อเข้าใช้ Google…" | ตอน Deploy ตั้ง *Who has access* ไม่ใช่ **Anyone** → แก้แล้ว **Deploy → Manage deployments → แก้ไข → Deploy ใหม่** |
| "ตรวจว่า URL ลงท้ายด้วย /exec" | ใช้ URL ตัวทดสอบ (`/dev`) → ต้องใช้ URL ที่ลงท้าย `/exec` |
| "ติดต่อฐานข้อมูลกลางไม่ได้…" | สัญญาณเน็ตขาด หรือวาง URL ผิด — ระบบลองซ้ำให้อัตโนมัติหนึ่งครั้งแล้ว |
| "เชื่อมต่อนานเกินไป" | เน็ตช้า ระบบรอถึง 45 วินาที กด **ทดสอบและเชื่อมต่อ** หรือล็อกอินอีกครั้ง |
| "เซสชันสิ้นสุดแล้ว…" | หมดเวลา 12 ชั่วโมง หรือมีการเปลี่ยนรหัส/ปิดบัญชี → ล็อกอินใหม่ |
| "ลองรหัสผ่านผิดหลายครั้งเกินไป…" | ระบบกันการเดารหัส รอ 10 นาทีแล้วลองใหม่ |

**หมายเหตุด้านเทคนิคที่ทำไว้ให้แล้ว** ระบบส่งคำสั่งเป็น POST ชนิด `text/plain` เพื่อไม่ให้เกิด CORS preflight ที่ Apps Script ตอบไม่ได้ · ตั้ง `redirect: follow` รองรับการเด้งไป `script.googleusercontent.com` ซึ่งเป็นพฤติกรรมปกติของ Apps Script · ไม่ใช้ cookie · ไม่พึ่ง localStorage ในการยืนยันตัวตน จึงใช้งานได้ในโหมดส่วนตัวของ Safari

## หลังติดตั้งแล้ว

- เพิ่ม/แก้ชื่อ/ตั้งรหัสใหม่/เปลี่ยน Role/ปิดบัญชี/ลบบัญชี → ทำจากมือถือได้ มีผลทันทีทุกเครื่อง **ไม่ต้องอัปไฟล์ ไม่ต้อง Deploy**
- ข้อมูลสมาชิกและการนมัสการ → อ่านสดจากชีตต้นทางทุกครั้งที่ล็อกอิน
- ผลพิจารณา → เก็บในแท็บ `Decisions` **แถวละ 1 รหัสสมาชิก** แยกจากข้อมูลต้นฉบับ พร้อมชื่อผู้บันทึกและเวลา
- ประวัติการใช้งาน → แท็บ `AuditLog`
- ปุ่มนำเข้า CSV ยังอยู่ในแผงผู้ดูแล (ใช้เมื่อไม่มีเน็ตหรือดูข้อมูลชุดเก่า)

## กติกาการคำนวณในรุ่นนี้

- **สถานภาพสมาชิกมาจากทะเบียนจริงหรือผลพิจารณาที่บันทึกไว้เท่านั้น** ระบบไม่เลื่อนหรือลดสถานภาพใครเองจากจำนวนครั้งที่มานมัสการ
- ขาดครบ 1 ปี → แสดงเป็น **"เข้าเกณฑ์ติดตาม/ตักเตือนตามระเบียบ"** (ข้อ 93.4(4) / 94.6(4))
- ขาดต่อเนื่องถึง 3 ปี → **"เข้าเกณฑ์ควรนำเข้าพิจารณาตามระเบียบ"** — สถานภาพเปลี่ยนเมื่อมีมติแล้วเท่านั้น
- ผู้ที่ทะเบียนยังไม่ระบุสถานภาพ → แสดงว่า **"ยังไม่ระบุสถานภาพในทะเบียน — ต้องตรวจสอบ"** ไม่เดาให้
- เกณฑ์ **อายุสมาชิกเกิน 1 ปี + มาเกิน 10 ครั้งใน 12 เดือน + ความต่อเนื่อง ≥ 50%** ใช้สำหรับวิเคราะห์และจัดลำดับเท่านั้น (ตัวกรอง "เข้าเกณฑ์เข้มแข็ง")
- **กฎเดิมที่ยกเลิกแล้วถูกถอดออกจากโค้ดจริง**: เกณฑ์ขาด 6 เดือน · การงดสิทธิ์ออกเสียงจากเกณฑ์ 6 เดือน · การกลับมาใหม่ต้องรอ 1 เดือน

## ความปลอดภัยในรุ่นนี้

- รหัสผ่าน: **การยืดกุญแจแบบทำเอง (repeated HMAC-SHA256 5,000 รอบ)** + salt ต่อบัญชี + ค่าลับฝั่งเซิร์ฟเวอร์ — ชีตเก็บเฉพาะค่าที่ย้อนกลับไม่ได้
  *ระบุตามจริง:* วิธีนี้ **ไม่ใช่** PBKDF2 / bcrypt / scrypt / Argon2 มาตรฐาน — Apps Script ไม่มีฟังก์ชันเหล่านั้นให้ใช้ จึงชดเชยด้วยการยืดกุญแจ 5,000 รอบร่วมกับการจำกัดจำนวนครั้งที่ลองรหัส และกำหนดรหัสขั้นต่ำ 8 ตัวทุกบัญชี
- **จำกัดการลองรหัส (แยกต่อบัญชี):** ผิดครบ 8 ครั้งใน 15 นาที → **บัญชีนั้นบัญชีเดียว** หยุดรับการล็อกอิน 10 นาที · ล็อกอินถูกต้องหนึ่งครั้งล้างตัวนับทันที · ทุกครั้งที่ถูกหยุดรับบันทึกใน AuditLog
- **ไม่มีการปิดการล็อกอินระดับระบบ** — ตัวนับความพยายามผิดรวมทุกบัญชีเก็บไว้เพื่อแจ้งเตือนใน AuditLog เท่านั้น (เมื่อครบ 40 ครั้งใน 15 นาทีจะบันทึกรายการ `alert-many-login-fails`) จึงไม่มีทางที่คนภายนอกจะยิงรหัสผิดเพื่อทำให้ทีมงานทั้งหมดเข้าระบบไม่ได้
- รหัสผ่านทุกบัญชี (ผู้ดูแล / ผู้แก้ไข / ผู้ดู) ต้องยาว **อย่างน้อย 8 ตัว** บังคับทั้งฝั่งเว็บและเซิร์ฟเวอร์
- ไม่มีรหัสใน URL · ไม่แสดงรหัสเดิมในหน้าโปรไฟล์ · ไม่มีชีตรหัสผ่านสาธารณะ · ไม่มีระบบรหัสสุ่มแจกอีก
- ตั้งรหัสใหม่ → เซสชันเก่าของบัญชีนั้นถูกตัดทันที (ผูก token กับรุ่นของรหัสผ่าน)
- ปิดบัญชี → token ที่ค้างอยู่ใช้ไม่ได้ทันที
- **กรองข้อมูลตาม Role ที่เซิร์ฟเวอร์**: Viewer ไม่ได้รับเบอร์โทร วันเกิด และหมายเหตุภายในเลย (ไม่ใช่ซ่อนในหน้าเว็บ) · Editor ได้หมายเหตุเพิ่ม · Admin ได้ครบ
- LockService กันการเขียนชนกันตอนสร้างผู้ดูแลคนแรก แก้บัญชี และบันทึกผลพิจารณา
- คำสั่งที่มีผลต่อข้อมูลรับผ่าน POST เท่านั้น

## รุ่นแก้ไข (10 ก.ย. 2569) — แก้อาการหน้าเว็บล่มและโหลดค้าง

**ต้องอัปทั้ง 2 ไฟล์** เพราะ backend เพิ่มคำสั่งใหม่

1. อัป `index.html` ทับที่ `v2/index.html` บน GitHub
2. เปิด Apps Script → วาง `apps-script/Code.gs` ทับโค้ดเดิม → บันทึก
3. **Deploy → Manage deployments → ดินสอ (Edit) → Version: New version → Deploy**
   (ถ้าไม่ทำขั้นนี้ URL เดิมจะยังเรียกโค้ดรุ่นเก่า และคำสั่งใหม่จะไม่ทำงาน)

**สิ่งที่เปลี่ยน**

- เข้าสู่ระบบเป็นขั้น: ยืนยันตัวตนสำเร็จ → เข้าหน้าหลักทันที แล้วจึงโหลดข้อมูลสมาชิก → ประวัตินมัสการ → ผลพิจารณา แยกคำสั่งกัน มีแถบบอกสถานะแต่ละขั้น
- ถ้าขั้นใดล้มเหลว **ไม่เด้งออกจากระบบ** — ขึ้นปุ่ม "ลองโหลดอีกครั้ง" ให้โหลดซ้ำเฉพาะส่วนที่ค้าง
- รายชื่อบัญชีโหลดเมื่อเปิดแผงโปรไฟล์เท่านั้น (ไม่หน่วงการเข้าใช้งาน) และถ้าอ่านไม่สำเร็จ หน้าหลักยังใช้งานได้ปกติ
- ข้อความแจ้งเหตุแยกจากกันชัดเจน: รหัสผิด / ติดต่อระบบเข้าสู่ระบบไม่ได้ / เข้าสู่ระบบแล้วแต่ข้อมูลช้า / ประวัตินมัสการช้า — ไม่เหมารวมว่า "อินเทอร์เน็ตช้า" อีก
- เวลารอต่อคำสั่งขยายเป็น 60 วินาที (ข้อมูลสมาชิกและประวัตินมัสการ) และลองซ้ำอัตโนมัติหนึ่งครั้ง
- ในแผงโปรไฟล์มีปุ่ม **"วัดเวลาที่ใช้แต่ละขั้น"** — กดแล้วจะเห็นว่าเวลาไปหมดที่ขั้นใด (อ่านทะเบียน / อ่านประวัติ / ตรวจรหัส / อ่านผลพิจารณา) ใช้ตัดสินใจก่อนปรับค่าใด ๆ · ผลถูกบันทึกใน AuditLog ด้วย โดยไม่มีรหัส ไม่มี token และไม่มีข้อมูลส่วนบุคคล
- Editor ไม่เห็นส่วนนำเข้า CSV และไม่เห็นการจัดการบัญชีแล้ว

**หากยังช้า** ให้กดปุ่มวัดเวลา แล้วแจ้งตัวเลขที่ได้ — จะรู้ได้ว่าคอขวดอยู่ที่การอ่านสเปรดชีตหรือการตรวจรหัสผ่าน แล้วจึงแก้ให้ตรงจุดโดยไม่ลดความปลอดภัยแบบเดา

## รุ่นแก้ไขเพิ่มเติม — คอลัมน์เวลาในชีตลงชื่อนมัสการ

**อาการที่แก้:** ชีต worshipRegister ที่สร้างจาก AppSheet มีหัวคอลัมน์แรกเป็นชื่อเฉพาะ (เช่น `Apml (นมัสการ)`) ไม่ใช่คำว่า "วันที่" หรือ "Timestamp" ตัวกรองคอลัมน์จึงมองไม่เห็นและตัดทิ้ง ทำให้ประวัติการนมัสการหายทั้งหมด

**วิธีแก้:** ระบบตรวจหาคอลัมน์วันเวลา **จากค่าจริงในเซลล์** (รองรับ `2567-07-07 10:16:22` และ `7/7/2567 10:16` ทั้ง พ.ศ. และ ค.ศ.) แล้วบังคับรวมคอลัมน์นั้นเสมอ — **ไม่ต้องแก้ชื่อคอลัมน์ในชีต ไม่กระทบ AppSheet**
คอลัมน์วันเกิดถูกกันไว้ไม่ให้ถูกเลือกโดยเด็ดขาด และถ้าหาคอลัมน์เวลาไม่พบ ระบบจะ**ไม่ส่งข้อมูลออกเลย** (fail-closed) พร้อมแจ้งสาเหตุ

อยากตรวจว่าชีตของคุณถูกอ่านอย่างไร: ในหน้า Apps Script เลือกฟังก์ชัน **`checkColumnAccess`** → Run → ดูที่ Execution log จะบอกว่าตรวจพบคอลัมน์เวลาคอลัมน์ไหน และแต่ละ Role เห็นคอลัมน์อะไรบ้าง (ไม่แสดงข้อมูลสมาชิก)

**สัญญารูปแบบข้อมูลระหว่างเว็บกับเซิร์ฟเวอร์ (แก้การชนกันของชื่อฟิลด์)**
- `ping` → `{ ok, kind:'ping', accountCount:ตัวเลข, needBootstrap }` — **ไม่มีฟิลด์ `accounts` อีกต่อไป**
- `list` → `{ ok, kind:'accountList', count, accounts:[…] }` — เป็นคำสั่งเดียวที่ใช้ชื่อ `accounts` และเป็นอาเรย์เสมอ
นี่คือต้นเหตุที่ทำให้หน้าเว็บเคยล่มด้วยข้อความ `...map is not a function` — ตอนนี้ปิดสนิททั้งสองฝั่ง
